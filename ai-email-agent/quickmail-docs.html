Como o Quick Mail funciona

Quick Mail é um agente de email inteligente. Ele lê sua caixa do Gmail, classifica cada thread por prioridade usando Claude AI, e permite gerar rascunhos de resposta sob demanda — tudo em uma interface com visual de aurora borealis.

Python · FastAPI Next.js 15 · TypeScript Anthropic Claude Haiku Gmail Threads API Three.js · GLSL Tailwind CSS

Responsabilidade de cada arquivo
● gmail_connect.py

Gerencia autenticação OAuth2 com o Google. Não sabe nada sobre emails, análise ou interface — só sabe como provar ao Google que o programa tem permissão de acesso. Retorna um objeto service que os outros módulos usam.

● agente.py

O cérebro. Busca threads do Gmail por escopo temporal, filtra as que não precisam de ação, analisa cada uma com Claude Haiku, mantém o histórico em memória, gera respostas sob demanda e verifica se o usuário já respondeu.

● api.py

A ponte entre Python e JavaScript. Expõe todas as funções do agente como endpoints HTTP que o frontend pode chamar via fetch(). Valida parâmetros de entrada e trata erros.

● dashboard.py

O ponto de entrada do sistema. Inicia o servidor FastAPI e o servidor Next.js como subprocessos paralelos, abre o navegador automaticamente e garante encerramento limpo dos dois processos ao fechar.

● ui/

Aplicação Next.js completa. Renderiza os emails em cards com liquid glass design sobre um fundo animado em WebGL, gerencia estado complexo de UX (dispensar, ordenar, gerar resposta, abrir no Gmail) e faz polling periódico na API.

Organização dos arquivos

Dois sistemas distintos na mesma pasta — backend Python e frontend Next.js — cada um com sua estrutura interna.

⚠.env, credentials.json e token.json nunca vão ao GitHub. Contêm chaves de acesso reais. O .gitignore garante isso automaticamente. Se algum desses arquivos vazar, terceiros podem usar sua conta do Gmail e sua chave Anthropic.

Por que backend e frontend separados?

Python é ideal para operações de I/O pesado, chamadas a APIs externas e lógica de negócio. JavaScript/React é o padrão para interfaces modernas. Separar os dois permite que cada parte use a melhor ferramenta para sua tarefa — e em produção, podem rodar em servidores diferentes.

Por que ambiente virtual (.venv)?

Cada projeto Python pode depender de versões diferentes das mesmas bibliotecas. O .venv isola todas as dependências dentro da pasta do projeto, evitando conflitos com outros projetos na mesma máquina. O npm install do Node.js faz o equivalente com a pasta node_modules/.

Backend — módulo 01

gmail_connect.py

Responsabilidade única: provar ao Google que o programa tem permissão para acessar o Gmail. Retorna um objeto de conexão autenticada que os outros módulos usam.

Por que autenticação é necessária

O Google não permite que qualquer programa acesse sua caixa de email livremente. O protocolo OAuth2 permite que o usuário autorize o acesso sem nunca revelar sua senha ao programa. O programa recebe um token de acesso limitado às permissões declaradas.

As importações
pythongmail_connect.py
from google.oauth2.credentials import Credentials from google_auth_oauthlib.flow import InstalledAppFlow from google.auth.transport.requests import Request from googleapiclient.discovery import build import os
ImportaçãoFunção
CredentialsRepresenta o token de acesso. Pode ser serializado em JSON, salvo em arquivo e reutilizado.
InstalledAppFlowConduz o fluxo OAuth2 para apps instalados: abre o navegador, captura o código de autorização, troca por token.
RequestRenova um token expirado usando o refresh_token, sem abrir o navegador de novo.
buildConstrói o cliente da API do Gmail a partir das credenciais. Retorna o objeto service.
osVerifica a existência do token.json no disco com os.path.exists().
O SCOPE — permissões declaradas
python
SCOPES = ['https://www.googleapis.com/auth/gmail.readonly']

O Google exige que você declare explicitamente quais permissões está pedindo. gmail.readonly significa acesso de leitura apenas — o agente pode ver emails mas não enviar, apagar ou modificar. Se futuramente precisar de envio, adiciona-se gmail.send.

A função conectar_gmail()
pythongmail_connect.py
def conectar_gmail(): creds = None # Tenta reutilizar token salvo if os.path.exists('token.json'): creds = Credentials.from_authorized_user_file('token.json', SCOPES) if not creds or not creds.valid: if creds and creds.expired and creds.refresh_token: creds.refresh(Request()) # renova sem abrir navegador else: flow = InstalledAppFlow.from_client_secrets_file( 'credentials.json', SCOPES ) creds = flow.run_local_server(port=0) # abre navegador with open('token.json', 'w') as token: token.write(creds.to_json()) # salva para reutilizar service = build('gmail', 'v1', credentials=creds) return service

Backend — módulo 02

agente.py

O cérebro do sistema. Busca threads do Gmail filtradas por período, analisa cada uma com Claude Haiku, mantém o histórico em memória e gerencia o loop de verificação em background.

Estado global e inicialização
pythonagente.py
import json, time, threading from datetime import datetime from gmail_connect import conectar_gmail from anthropic import Anthropic from dotenv import load_dotenv load_dotenv() # lê .env → disponibiliza ANTHROPIC_API_KEY client = Anthropic() # abre conexão com a API do Claude # Estado compartilhado — acessado pela thread do loop e pelo FastAPI historico = [] # emails analisados _ids_processados = set() # IDs já vistos — busca O(1), sem duplicatas rodando = False # interruptor do loop thread_agente = None # referência à thread em execução # Mapa de escopos temporais em segundos ESCOPO_SEGUNDOS = { "hora": 3600, "dia": 86400, "semana": 604800, }
💡Por que set para _ids_processados? Um set nunca contém duplicatas e a verificação de pertinência (x in set) é O(1) — constante, independente do tamanho. Uma lista exigiria percorrer todos os elementos a cada verificação, ficando mais lento conforme cresce.
processar_emails() — o pipeline principal
pythonagente.py
def processar_emails(quantidade=5, escopo="dia"): global historico, _ids_processados # Calcula o timestamp de início do período after_epoch = int(time.time()) - ESCOPO_SEGUNDOS.get(escopo, 86400) service = conectar_gmail() resultado = service.users().threads().list( userId='me', maxResults=quantidade, labelIds=['INBOX'], q=f"after:{after_epoch}", # filtra por período na query ).execute() for t in resultado.get('threads', []): if t['id'] in _ids_processados: continue # já processado — pula thread_data = service.users().threads().get( userId='me', id=t['id'], format='full' ).execute() messages = thread_data.get('messages', []) if not messages: continue # Ignora threads onde o usuário já respondeu por último last_labels = messages[-1].get('labelIds', []) if 'SENT' in last_labels: continue # Extrai dados do primeiro email da thread first = messages[0] headers = first['payload']['headers'] assunto = next((h['value'] for h in headers if h['name'] == 'Subject'), 'Sem assunto') remetente = next((h['value'] for h in headers if h['name'] == 'From'), 'Desconhecido') trecho = first.get('snippet', '') analise = analisar_email(remetente, assunto, trecho) historico.append({ "id": t['id'], "timestamp": datetime.now().strftime("%d/%m %H:%M"), "internalDate": int(first.get('internalDate', 0)), "remetente": remetente, "assunto": assunto, "trecho": trecho, "resposta_sugerida": None, **analise, # expande prioridade, categoria, acao_sugerida }) _ids_processados.add(t['id'])
💡Por que threads e não mensagens? Uma conversa de email tem várias mensagens. Trabalhar com a thread inteira evita mostrar o mesmo assunto múltiplas vezes. O filtro 'SENT' in last_labels detecta se a última mensagem da thread foi enviada pelo usuário — se sim, ele já respondeu e não precisa ser lembrado.
🔍O que é **analise? O operador ** desempacota um dicionário dentro de outro. Se analise = {"prioridade": "alta", "categoria": "trabalho"}, então {**analise} adiciona essas chaves diretamente no dicionário maior, sem escrever cada campo manualmente.
analisar_email() — classificação com Claude
pythonagente.py
def analisar_email(remetente, assunto, trecho): response = client.messages.create( model="claude-haiku-4-5-20251001", # rápido e econômico max_tokens=200, # JSON pequeno — 200 suficiente messages=[{"role": "user", "content": f"""..."""}] ) texto = response.content[0].text limpo = texto.replace("```json", "").replace("```", "").strip() return json.loads(limpo) # string → dicionário Python
⚡Por que Claude Haiku? Haiku é o modelo mais rápido e barato da família Claude — processa tokens a alta velocidade por fração do custo do Sonnet. Classificação de emails é uma tarefa de raciocínio simples; não precisa do modelo mais capaz. Em um sistema que processa dezenas de emails, a diferença de custo é significativa.
gerar_resposta() — sob demanda
pythonagente.py
def gerar_resposta(email_id): email = next((e for e in historico if e['id'] == email_id), None) if not email: return None response = client.messages.create( model="claude-haiku-4-5-20251001", max_tokens=500, messages=[{"role": "user", "content": f""" Escreva uma resposta profissional e personalizada para este email. Responda apenas com o corpo da resposta, sem assunto ou saudações genéricas. De: {email['remetente']} Assunto: {email['assunto']} Conteúdo: {email['trecho']} Ação sugerida: {email.get('acao_sugerida', '')}"""}] ) resposta = response.content[0].text.strip() email['resposta_sugerida'] = resposta # atualiza o histórico em memória return resposta

A geração de resposta é separada da análise por dois motivos: a maioria dos emails (alertas, notificações, spam) não precisa de resposta, evitando chamadas à API desnecessárias. E quando gerada, o contexto da acao_sugerida (calculada na análise) guia a qualidade da resposta.

Loop, threads e controle
pythonagente.py
def loop_agente(intervalo=60, escopo="dia"): global rodando while rodando: processar_emails(escopo=escopo) time.sleep(intervalo) # aguarda antes de verificar de novo def iniciar(intervalo=60, escopo="dia"): global rodando, thread_agente if not rodando: rodando = True thread_agente = threading.Thread( target=loop_agente, args=(intervalo, escopo), daemon=True ) thread_agente.start() def parar(): global rodando rodando = False # o loop termina na próxima iteração
🔮daemon=True faz a thread depender do processo principal. Quando o uvicorn encerra, a thread do agente morre automaticamente — sem processos zumbis rodando em background invisíveis.
Resumo

Busca threads filtradas por período, ignora as já respondidas, analisa com Claude Haiku em JSON estruturado, salva no histórico global e repete em loop numa thread paralela. Funções separadas para análise e geração de resposta otimizam custo.

Backend — módulo 03

api.py

Servidor FastAPI que expõe todas as funções do agente como endpoints HTTP. É a ponte entre o frontend JavaScript e o backend Python — sem ele, os dois lados não conseguem se comunicar.

Configuração e CORS
pythonapi.py
from typing import Literal from fastapi import FastAPI, HTTPException, Path from fastapi.middleware.cors import CORSMiddleware from pydantic import BaseModel, Field import agente app = FastAPI(title="Quick Mail API") app.add_middleware( CORSMiddleware, allow_origins=["http://localhost:3000", "http://127.0.0.1:3000"], allow_methods=["GET", "POST"], allow_headers=["Content-Type"], )
🔒O que é CORS? Browsers bloqueiam por segurança requisições JavaScript de uma origem para outra. Como Next.js roda em :3000 e FastAPI em :8000, são origens diferentes. O middleware CORS responde aos browsers com cabeçalhos que autorizam essas origens específicas.
Validação com Pydantic
pythonapi.py
class StartRequest(BaseModel): quantidade: int = Field(default=5, ge=1, le=50) intervalo: int = Field(default=60, ge=30, le=3600) escopo: Literal["hora", "dia", "semana"] = "dia"

ge = greater or equal, le = less or equal. Se o frontend mandar quantidade: 200, o FastAPI rejeita automaticamente com erro 422 — sem precisar escrever nenhuma validação manual. Literal do typing restringe o campo a exatamente esses três valores.

Todos os endpoints
GET
/api/status
Retorna {"running": bool, "total": int}. O frontend faz polling neste endpoint para atualizar o indicador de status na barra superior.
GET
/api/emails
Retorna o array historico completo do agente. O frontend chama a cada intervalo configurado para manter a lista de cards atualizada.
POST
/api/start
Aceita StartRequest no body. Processa emails imediatamente, depois inicia o loop em background. Retorna quantos emails novos foram encontrados.
POST
/api/stop
Para o loop do agente definindo rodando = False. O histórico permanece em memória — emails continuam visíveis.
GET
/api/emails/{email_id}/respondido
Consulta o Gmail para verificar se a thread foi respondida (última mensagem tem label SENT). O frontend faz polling aqui após o usuário abrir o rascunho no Gmail.
POST
/api/emails/{email_id}/resposta
Chama agente.gerar_resposta() para o ID especificado. Retorna o texto do rascunho gerado pelo Claude. Chamado apenas no clique do usuário.
💡O FastAPI gera documentação interativa automática em http://localhost:8000/docs enquanto o servidor está rodando. Você pode testar todos os endpoints direto no browser sem precisar de curl ou Postman.
Resumo

Expõe o agente Python como serviço HTTP com 6 endpoints. Configura CORS para o Next.js, valida entradas com Pydantic e propaga exceções como respostas HTTP estruturadas.

dashboard.py

Este arquivo não tem interface visual. Sua única função é orquestrar os dois processos que compõem o sistema — garantindo que subam na ordem certa e sejam encerrados corretamente.

import subprocess, sys, os, time, webbrowser, signal BASE = os.path.dirname(os.path.abspath(__file__)) # pasta do próprio arquivo UI_DIR = os.path.join(BASE, "ui") npm_cmd = "npm.cmd" if sys.platform == "win32" else "npm" # compatibilidade Windows def main(): api_proc = subprocess.Popen([ sys.executable, "-m", "uvicorn", "api:app", "--host", "0.0.0.0", "--port", "8000", "--reload", ], cwd=BASE) ui_proc = subprocess.Popen([npm_cmd, "run", "dev"], cwd=UI_DIR) time.sleep(5) webbrowser.open("http://localhost:3000") def shutdown(_sig, _frame): api_proc.terminate() ui_proc.terminate() sys.exit(0) signal.signal(signal.SIGINT, shutdown) if hasattr(signal, "SIGTERM"): signal.signal(signal.SIGTERM, shutdown) api_proc.wait() # mantém o script vivo enquanto a API roda

Comunicação com a API
typescriptpage.tsx
const API = 'http://localhost:8000'; // useCallback evita recriar a função a cada render const fetchEmails = useCallback(async () => { try { const res = await fetch(`${API}/api/emails`); if (!res.ok) throw new Error(); setEmails(await res.json()); setConnected(true); } catch { setConnected(false); } }, []); // Polling: atualiza emails a cada intervalo quando rodando useEffect(() => { if (!running) return; const id = window.setInterval(fetchEmails, refreshSecs * 1000); return () => window.clearInterval(id); // cleanup ao parar }, [running, refreshSecs, fetchEmails]);
💡Por que useCallback? Sem ele, fetchEmails seria uma nova função a cada render, fazendo o useEffect disparar infinitamente (já que a função está nas dependências). useCallback memoriza a função entre renders.
Abertura direta no Gmail
typescriptpage.tsx
const openInGmail = (email: Email, reply: string) => { const to = extractEmail(email.remetente); // extrai email de "Nome <email>" const su = encodeURIComponent(`Re: ${email.assunto}`); const body = encodeURIComponent(reply); window.open( `https://mail.google.com/mail/?view=cm&to=${to}&su=${su}&body=${body}`, '_blank' ); setAwaitingReply(prev => new Set(prev).add(email.id)); // começa monitorar };

A URL mail.google.com/?view=cm abre o Gmail no modo compose com campos pré-preenchidos. Após abrir, o frontend começa a verificar periodicamente se a thread recebeu um SENT — quando sim, o card é dispensado automaticamente.

Frontend — componente visual

animated-shader-background

Fundo animado em aurora borealis renderizado na GPU via Three.js e GLSL. Zero impacto no thread JavaScript — roda completamente no hardware gráfico.

O que é um shader GLSL

GLSL (OpenGL Shading Language) é uma linguagem de programação que roda na GPU. Um fragment shader recebe a posição de cada pixel e o tempo, e retorna a cor daquele pixel. Como a GPU processa milhares de pixels em paralelo, o resultado é animação fluida sem custo para o JavaScript.

Configuração Three.js
typescriptanimated-shader-background.tsx
const material = new THREE.ShaderMaterial({ uniforms: { iTime: { value: 0 }, // tempo — incrementado a cada frame iResolution: { value: new THREE.Vector2(w, h) }, // tamanho da tela }, vertexShader: `void main() { gl_Position = vec4(position, 1.0); }`, fragmentShader: `...`, // lógica da aurora borealis }); const geometry = new THREE.PlaneGeometry(2, 2); // plano que cobre a tela inteira const mesh = new THREE.Mesh(geometry, material); scene.add(mesh);
O loop de animação
typescript
const animate = () => { material.uniforms.iTime.value += 0.01; // avança o tempo renderer.render(scene, camera); // renderiza o frame na GPU animationId = requestAnimationFrame(animate); // agenda o próximo frame };

requestAnimationFrame é a forma correta de criar loops de animação no browser — sincroniza com o refresh rate da tela (geralmente 60fps), pausa automaticamente quando a aba fica em background, e não bloqueia o thread principal.

A lógica visual — aurora borealis

O shader usa Fractal Brownian Motion (fbm): camadas de ruído acumuladas com amplitudes e frequências diferentes, criando movimento orgânico e não repetitivo. A cada frame, iTime incrementa e o ruído se move, animando a aurora. O efeito de shake sutil (vec2 shake) adiciona microtremor.

🎨O cleanup é importante: renderer.dispose() e cancelAnimationFrame(animationId) no return do useEffect liberam memória e param a GPU quando o componente é desmontado — evitando vazamentos de memória em navegação entre páginas.

A animação de dismiss

@keyframes dismiss-right { 0% { opacity: 1; transform: translateX(0); max-height: 300px; margin-bottom: 0.5rem; } 60% { opacity: 0; transform: translateX(80px); max-height: 300px; margin-bottom: 0.5rem; } 100% { opacity: 0; transform: translateX(80px); max-height: 0; margin-bottom: 0; } } .dismissing { animation: dismiss-right 0.38s ease-out forwards; pointer-events: none; overflow: hidden; }

A animação tem três fases: desliza para a direita enquanto fica transparente, depois colapsa a altura para zero — fechando o espaço sem salto brusco. max-height: 0 combinado com overflow: hidden é a técnica padrão para colapsar elementos com animação CSS.

No React, a classe dismissing é aplicada ao card quando o usuário clica em dispensar. Após 400ms (ligeiramente antes da animação terminar), o ID é adicionado ao set dismissed — removendo o card da renderização.

O que é uma API REST

REST (Representational State Transfer) é um padrão de comunicação via HTTP. O cliente (frontend) faz requisições para URLs com métodos (GET, POST) e recebe respostas em JSON. Cada URL representa um recurso ou ação.

Engenharia de prompt

Dois prompts especializados para tarefas distintas — como foram construídos e por que as decisões de design importam.

Prompt 1 — Classificação
promptanalisar_email()
Analise este email e responda em JSON com exatamente este formato: { "prioridade": "alta / média / baixa", "categoria": "trabalho / financeiro / pessoal / spam / outro", "acao_sugerida": "uma frase curta com o que fazer" } Email: De: {remetente} Assunto: {assunto} Trecho: {trecho}
Decisão de designPor que importa
Instrução antes dos dadosModelos seguem melhor instruções quando elas precedem o conteúdo a ser processado.
Formato JSON explícito com exemploMostrar a estrutura é mais eficaz que descrever em palavras. O modelo copia o padrão fornecido.
Valores enumerados"alta / média / baixa" restringe opções. Sem isso, o modelo poderia retornar "urgente", "crítico", "importante" — impossível de parsear previsivelmente.
Sem "resposta_sugerida"Gerada por demanda em função separada. A maioria dos emails não precisa de resposta — evita chamadas desnecessárias.
Prompt 2 — Geração de resposta
promptgerar_resposta()
Escreva uma resposta profissional e personalizada para este email. Responda apenas com o corpo da resposta, sem linhas de assunto ou saudações genéricas. De: {remetente} Assunto: {assunto} Conteúdo: {trecho} Ação sugerida: {acao_sugerida}
Decisão de designPor que importa
"sem saudações genéricas"Sem essa instrução, o Claude começa com "Prezado [Nome], espero que esteja bem...". A instrução negativa é tão importante quanto a positiva.
"apenas com o corpo"Evita que o Claude inclua Subject: ou outros campos de email que o usuário não quer.
Inclui acao_sugerida do Prompt 1A análise do primeiro prompt guia a qualidade do segundo. "Marcar reunião" produz resposta propondo horários. Os dois prompts se complementam.
max_tokens=500Respostas de email geralmente cabem em ~300 tokens. 500 dá margem sem desperdiçar.
Princípio

Prompts menores e específicos produzem resultados mais previsíveis, mais rápidos e mais baratos do que um único prompt que tenta fazer tudo de uma vez. Separar classificação de geração de resposta é uma decisão de arquitetura, não apenas de prompt.

Respostas para entrevistas
Pergunta: "Me explique a arquitetura"

Backend FastAPI em Python cuida de toda lógica e acesso às APIs externas. Frontend Next.js em TypeScript cuida da interface. Uma API REST na porta 8000 conecta os dois. Um orquestrador Python sobe ambos como subprocessos e garante shutdown limpo.

Pergunta: "Como otimizou custo da API do Claude?"

Duas decisões: usei Haiku em vez de Sonnet — mesma família, fração do custo, suficiente para classificação simples. E separei geração de resposta para ser sob demanda — a maioria dos emails não precisa de resposta, então a chamada à API só acontece quando o usuário pede.

Pergunta: "O que faria diferente para produção?"

Banco de dados persistente (SQLite ou PostgreSQL) em vez de variáveis globais em memória. Autenticação na API para múltiplos usuários. Rate limiting para cotas da Gmail API. Testes unitários para cada módulo. Deploy separado do frontend (Vercel) e backend (Railway ou Fly.io).

Pergunta: "Me explique o efeito visual do fundo"

Three.js cria um plano 2D cobrindo a tela. Um ShaderMaterial com fragment shader GLSL calcula a cor de cada pixel na GPU usando Fractal Brownian Motion — ruído acumulado em camadas simulando movimento orgânico. Os cards usam backdrop-blur do CSS sobre o shader para o efeito de vidro fosco.
